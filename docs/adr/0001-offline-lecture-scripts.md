# 讲稿离线生成，运行时不用 LLM 主讲

讲师讲的每一课都依据一份事先生成、提交进仓库的讲稿。讲稿由 Claude 在 Claude Code 会话里离线写好，走订阅计费。讲课时讲师照着讲稿推进，不让 LLM 现场决定讲什么。

运行时只在两处调用 LLM：

- 代问：由助教（DeepSeek）回答。
- 换个讲法：优先用 Kimi `k3.1-pro`，缺 Kimi key 时改用 DeepSeek。

## 为什么这样定

我们比较过"每到一个小节就让 LLM 现场生成讲解"的方案，最后选择离线讲稿，原因有三点：

1. **质量稳定，且可调试**：讲稿离线生成时，能看到全课上下文，可以反复打磨；出了问题能定位到具体某一步。
2. **零延迟**：讲师的音频可以提前合成好，上课时直接播放，不用等模型推理和语音合成。推理模型一句话就要几秒。
3. **成本低**：讲稿生成走 Claude 订阅，按量计费的 API 只在学生主动触发时才调用。

代价是灵活性。讲师不会根据学生的状态即兴调整整堂课，只能对当前这一步"换个讲法"。按学生提问改写后续讲稿的能力留到以后，作为在讲稿之上的增量来做，而不是改成现场生成。

学生不需要审阅讲稿。讲稿的质量由 `lessons/lecturer/AUTHORING.md` 里的生成规范保证。
