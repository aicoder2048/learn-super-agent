# 讲稿生成规范

讲师照着**讲稿**讲一课。讲稿由 Claude 在 Claude Code 里离线生成（理由见 `docs/adr/0001-offline-lecture-scripts.md`），学生不需要审阅，所以质量全靠这份规范来保证。名词的含义以仓库根目录的 `GLOSSARY.md` 为准。

## 生成一课讲稿的流程

1. 通读这一课的页面（`lessons/SAxx-*.html`）和原文对应的章节（`docs/articles/super-agent-design-exploration.md`）。
2. 挑出 2–4 个**重点话题**，每个小节最多 1 个，优先选心智模型、关键概念或设计框架。
3. 按小节顺序写步骤，存为 `lessons/lecturer/scripts/SAxx.json`。
4. 校验并预合成音频：`just lecture-audio SAxx`。
5. 从头到尾听一遍：`just lecture SAxx`。

## 文件格式

```json
{
  "lesson": "SA02-two-layer.html",
  "title": "双层架构：Router 与 Worker",
  "steps": [ { "id": "s1-01", "section": "s1", "kind": "say", "target": "#s1 h2", "say": "……" } ]
}
```

每一步都有这些字段：

| 字段 | 含义 |
|---|---|
| `id` | 唯一，建议写成 `小节-序号`，如 `s3-02` |
| `section` | 所在小节的 id（`s1`…），`--from` 靠它定位 |
| `kind` | `say`、`demo`、`proxy`、`quiz` 四种之一 |
| `target` | CSS 选择器。讲这一步时，页面滚到它并高亮 |
| `nth` | 可选。`target` 匹配到多个元素时，取第几个（从 0 开始） |
| `say` | 讲师说的话 |

不同 `kind` 还需要额外字段：

- **say**：普通讲解，没有额外字段。
- **demo**：讲师操作演示。需要 `actions`，它们会在讲师开口**之前**依次执行，所以 `say` 要描述操作后的结果（"我把间隔拖到半分钟，你看……"）。支持三种 action：
  - `{"set": "#d1-g", "value": "0.5"}`：设置滑块或下拉框的值，并触发 `input`/`change` 事件
  - `{"set": "#d1-fix", "value": "true"}`：勾选（或用 `"false"` 取消勾选）复选框。复选框一律用 `set` 给出确定状态，**不要用 `click`**：click 是切换，学生按 ← 回放这一步时状态会反过来，和讲解对不上
  - `{"click": "#btn"}`：点击元素
  - `{"wait": 800}`：等待若干毫秒
- **proxy**：代问。`say` 是讲师引出问题的话（"很多同学这里会问……我们请助教来回答"）；`question` 是讲师在右栏公开发给助教的问题。
- **quiz**：自测题，`target` 指向 `.quiz`，用 `nth` 选第几题。流程是：讲师用 `say` 读题和选项，然后自动暂停，等学生作答；学生按空格继续后，如果还没作答，讲师替他点出正确答案，再讲 `explain`。

## 写作要求

**说的话，不是写的字。**
- 口语化，用短句，一句话不超过 30 个字。不要照念页面原文，要像老师在黑板前讲解。
- 每一步的 `say` 控制在 40–150 字。一段太长，就拆成两步。
- 不要念表格、代码、公式符号。要讲的是"这张表说明了什么"。
- 英文术语照常说（Router、Worker、Prefill），不用硬译。数字写成读得出来的形式（"二点五秒"可以直接写成"2.5 秒"，TTS 能读）。
- 不要用 Markdown、括号注释或表情符号，它们会被原样读出来或者读得很怪。

**重点话题由讲师亲自讲。**
- 先给结论，再给一个比方或场景，最后点出它和前后内容的联系。
- 重点话题可以连续占两三步，配合高亮页面上对应的段落、图或演示。

**代问只做补充，每课 1–2 次。**
- 选学生最可能卡住的地方，问的是讲师**讲过之后**仍然自然会冒出来的疑问，例如边界条件、反例、和熟悉系统的类比。不要让助教替讲师讲重点。
- 问题本身要带约束，例如"请用 200 字以内回答，先给结论"。
- 代问前那一步的 `target` 应该指向相关小节，因为助教会把"正在看的小节"当作上下文。

**演示要动手。**
- 每个演示至少操作一次，演示两种对比状态（例如"先看间隔大时……再拖小……"）。
- 操作前先说要看哪里，操作后说看到了什么、说明了什么。

**区分原文和补充。** 页面上标为"补充"的内容是课程作者的解释。讲到它们时说"课程这里补充了一个比方"，不要说成原文的观点。

## 示例

```json
{ "id": "s1-03", "section": "s1", "kind": "demo", "target": "#demo1",
  "actions": [{ "set": "#d1-g", "value": "0.5" }, { "wait": 600 }],
  "say": "我把事件间隔拖到半分钟，让事件变得很密。你看第一行，单 Session 的全部完成时间还是 48 分钟，一点没变。" },
{ "id": "s3-04", "section": "s3", "kind": "proxy", "target": "#s3",
  "say": "讲到这儿，很多同学会问：Router 只用轻量模型，它判断错了怎么办？我们请助教来说说。",
  "question": "Router 用轻量模型，如果它把事件分派错了 Worker，会有什么后果？原文有没有兜底机制？请 200 字以内回答，先给结论。" }
```
